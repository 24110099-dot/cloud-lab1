02 Cloud Computing

In my own words, cloud computing means renting computing power, storage and software from a provider over the Internet instead of buying and maintaining my own servers. When I need a resource, I request it through a web console, a command-line tool or an API, and it is ready in minutes. When I no longer need it, I release it and stop paying.

The provider keeps huge pools of hardware in its data centers and shares them between many customers, so a small team can use the same reliable infrastructure as a large company. Capacity can grow during a busy period, such as course registration week, and shrink again afterwards. Every resource is measured, so cost follows actual usage (OpEx) rather than a large upfront purchase (CapEx).

The five essential characteristics (NIST)

  • On-demand self-service
  • Broad network access
  • Resource pooling
  • Rapid elasticity
  • Measured service

03 Cloud Services

The three service models differ in how much of the technology stack the provider manages and how much control stays with the customer.

IaaS

Infrastructure as a Service

The provider supplies virtual machines, storage volumes and networks. I still install and manage the operating system, runtime and application myself, so I get the most control but also the most work. Typical users are system administrators and architects.

Example: Amazon EC2 — launch a virtual Linux server and configure it yourself.

PaaS

Platform as a Service

The provider manages servers, operating system and runtime. Developers only upload their code and data, and the platform handles deployment, scaling and patching. Less OS-level control, but much faster delivery.

Example: AWS Elastic Beanstalk — deploy a Python or Node.js web app without managing servers.

SaaS

Software as a Service

A complete, ready-to-use application delivered over the Internet. End users simply sign in through a browser or app; the provider operates everything underneath, including updates and backups.

Example: Microsoft 365 — email, Word and Teams used directly in the browser.

How it was deployed

  1. Created index.html, style.css and the assets/ folder locally.
  2. Pushed the files to a public GitHub repository named cloud-lab1.
  3. Opened Settings → Pages → Deploy from a branch and selected main / (root).
  4. GitHub built the site and published it on its global CDN with a free HTTPS certificate.
  5. Verified the URL in a normal and an incognito window on desktop and mobile.
